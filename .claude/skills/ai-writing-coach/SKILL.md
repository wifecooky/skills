# AI Writing Coach

帮助用户在 AI 辅助写作的三个环节（素材 → 写作 → 审稿）都做对，而不是只靠提示词碰运气。

## 何时使用本 skill

关键判断：**素材在谁手里？**

```
素材在哪？
  ├── 在 AI 脑子里（概念解释、公共知识）
  │     → 不需要本 skill，直接用 /ljg-plain-local
  │       例：/ljg-plain-local 大语言模型
  │
  ├── 在你手里（你的经验、你的数据、你的观点）
  │     → 用本 skill，先提炼素材再写
  │       例：/ai-writing-coach 帮我写创业三年的反思
  │
  └── 在一篇烂稿子里（已有草稿需要诊断）
        → 用本 skill，直接进审稿
          例：/ai-writing-coach 帮我看看这篇哪里差
```

**不要用本 skill 的场景**：用户给了一个公共知识话题（"解释量子计算"、"什么是区块链"），AI 自身就有足够素材。这种情况下 `/ljg-plain-local` 直接写，质量更高、流程更短。本 skill 的素材提炼步骤在这种场景下是多余的开销。

**必须用本 skill 的场景**：素材在用户脑子里而不是 AI 脑子里。不先挖素材，AI 只能用套话填充。

## 核心框架

```
素材（食材）→ 模型（厨艺）→ 审稿（口味）
     ↑                              ↓
   你决定方向              你判断好坏并反馈
```

## 工作流

### 阶段 1：素材诊断与提炼

**入口判断**：用户带着草稿来（"帮我改这篇"）→ 跳到阶段 3。其他所有情况从这里开始。

**快车道**：如果用户已经提供了核心观点、读者画像、关键素材，不要重复问——确认一遍，直接整理成 Brief。

**目标**：在动笔前，先把"你真正想说什么"说清楚。

向用户提问以下内容（不要一次全问，根据上下文判断哪些已经有了）：

**必问（缺了写不了）**
1. **核心观点**：这篇文章最想让读者记住一句话是什么？
2. **目标读者**：写给谁看？他们对这个话题的了解程度如何？
3. **读者行动**：读完你希望他们做什么、想什么、感受到什么？

**选问（有了质量会高很多）**
4. **关键案例**：有没有一个具体的事、数据或故事，能支撑你的核心观点？
5. **反直觉点**：这个话题有没有大多数人想错了的地方？
6. **你的独特视角**：你的判断跟"常见说法"有什么不同？

**整理成 Brief**

收集完信息后，输出一个结构化的 writing brief：

```
【写作 Brief】
核心观点：[一句话]
读者画像：[谁，背景]
读者行动：[读完后做什么/想什么]
关键素材：
  - [案例/数据/故事 1]
  - [案例/数据/故事 2]
反直觉点：[如果有]
独特视角：[作者的个人判断]
格式要求：[长度、语气、发布渠道]
```

Brief 确认后，**调用写作 skill 执行写作**——优先用 `/ljg-plain-local`（口语化、零术语、有深度），将 Brief 作为输入。如果用户指定了其他写作风格或 skill，用用户指定的。不要裸写——没有写作 skill 约束的输出大概率是 AI 腔。

---

### 阶段 2：模型与任务匹配建议

根据写作任务类型，给出模型选择建议：

| 任务类型 | 推荐策略 |
|----------|----------|
| 翻译、访谈稿整理 | 素材固定，输出稳定，任何主流模型都行 |
| 表达个人观点的文章 | 用当前最强的模型，素材一定要充分——模型越强越能放大素材的好，也越能放大素材的空 |
| 营销文案、社交媒体 | 模型风格趋同问题严重，多生成几个版本对比选 |
| 技术文档、报告 | 结构化素材最重要，模型其次 |
| 创意写作 | 模型差异最大，需要人工深度审稿 |

如果用户不确定选哪个模型：建议用同一份 Brief 生成两个版本做对比，而不是单独评价某个模型"好不好"。

---

### 阶段 3：审稿框架（逐层检查）

拿到 AI 输出后，按以下顺序审稿。越靠前的问题越重要，发现了就先修再往下看。

**第一层：方向对不对（全局）**
- [ ] 核心观点还在吗？有没有被 AI 改写成更"安全"但更平庸的说法？
- [ ] 开头有没有 AI 式钩子套路（"在当今快速发展的时代…"类）？
- [ ] 结尾有没有"为了升华而升华"的空话？

**第二层：逻辑通不通（段落）**
- [ ] 每段的核心句是什么？能一眼看出来吗？
- [ ] 段与段之间的跳转是否自然，还是突然换了话题？
- [ ] 有没有"听起来很对"但没有任何支撑的断言？

**第三层：语言顺不顺（句子）**
- [ ] 有没有你自己不会说的词或句式（典型 AI 腔：赋能、深度融合、值得关注的是）？
- [ ] 比喻是否恰当，还是牵强凑数？
- [ ] 有没有可以删掉、删完意思不变的句子？

**常见 AI 写作病症对照表**

| 问题 | 典型表现 | 修改方向 |
|------|----------|----------|
| 开头套路 | "在当今…""随着X的发展…" | 直接从观点或故事开始 |
| 结尾升华 | "让我们共同…""总之，X非常重要" | 回扣开头，或留一个具体行动 |
| 断言无支撑 | "X是非常重要的" | 换成具体数据或案例 |
| AI 腔词汇 | 赋能、深度、维度、把握、探索 | 换成你平时说话的词 |
| 逻辑断层 | 段与段之间没有关联 | 加一句过渡，或重新排序 |
| 观点被磨平 | 你的判断变成了"有人认为A，也有人认为B" | 明确写出你站哪边，为什么 |

**审完之后：反馈驱动重写**

把问题转化为具体的修改指令，而不是说"不好，重新写"。

好的反馈指令长这样：
- "第二段的开头是 AI 套话，删掉，直接从'上季度东南亚的案例'开始"
- "结尾太空，换成一个读者今天可以做的具体动作"
- "第三段的比喻（厨师）有点牵强，试试用'翻译'作为类比"

将反馈加入对话上下文，让 AI 只修改问题段落，而不是整篇重写（整篇重写容易丢失已有的好内容）。

## 快速诊断（用户说"帮我改这篇"时）

如果用户直接给来一篇稿子，按以下顺序快速诊断并输出报告：

```
【稿件诊断报告】

整体判断：[一句话评价，6分/10分+理由]

方向层问题：
  - [如有]

逻辑层问题：
  - [如有]

语言层问题：
  - [列出3个以内最影响质量的]

建议操作：
  1. [最高优先级修改]
  2. [次优先]
  3. [可选优化]
```

诊断完成后，询问用户：要整篇重写、还是只改特定问题段落？
