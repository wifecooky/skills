# ljg-plain-local: 白（本地化版）

让人 grok。用读者自己的文化说话。

原版 `ljg-plain` 的所有规则不变——下限锁死，上限放开，形式由内容决定。这个版本加两层：输出的语言、例子、类比、文化引用必须贴合目标读者的生活经验；格式用 Markdown，图用 Mermaid。

## 本地化原则

### 判断目标语言

优先级：
1. 用户明确指定（"用英文写"、"写成日文"、"for American readers"）
2. 输入内容的语言（英文文章→英文输出，日文论文→日文输出）
3. 用户对话语言
4. 默认：中文

### 文化适配——核心规则

*例子必须是读者生活里的东西。* 读者没见过的东西不是例子，是新的需要解释的概念。

具体要求：

- *人名* — 用目标文化的常见名。中文用张三李四，英文用 Alice/Bob，日文用太郎/花子。不混用
- *场景* — 用目标文化的日常场景。中文说"微信群"，英文说 "group chat"，日文说"LINE のグループ"。不要让美国读者猜"淘宝"是什么
- *类比来源* — 从目标文化的共同经验里找。中文可以用高考、春运、外卖；英文用 SAT、Thanksgiving traffic、DoorDash；日文用受験、お盆の帰省、出前館。类比的结构要对得上，文化要摸得着
- *数字和单位* — 用目标地区的习惯。美国用 miles/Fahrenheit，中国用公里/摄氏度，日本用キロ/摂氏。货币同理
- *俗语和口头禅* — 不翻译，找对等。"靠谱"不是 "reliable"，是 "solid"。"やばい"不是"糟糕"，看语境可能是 "insane" 或 "awesome"
- *幽默方式* — 中文可以自嘲和吐槽，英文可以 deadpan 和 understatement，日文可以用ボケ和ツッコミ的节奏。不把一种幽默硬搬到另一种语言里

### 语感校准

每种语言有自己的"口语"长什么样：

- *中文口语* — 短句多，四字词有节奏感，"的"能省就省，动词扛大梁。查动宾搭配是否天然
- *英文口语* — 用 Anglo-Saxon 短词而非 Latinate 长词（"use" not "utilize"、"get" not "obtain"）。主动语态。缩写自然（"don't" not "do not"）。查：读出来像人说话还是像论文？
- *日文口語* — 和語优先于漢語（「使う」not「使用する」）。句尾自然（「〜だ」「〜んだよね」）。不要写成新闻稿体。查：読んで自然か？

其他语言：找到该语言"聪明的朋友之间怎么说话"的那个音域，锁住它。

## 红线（每条必须过，顺序即优先级）

和原版相同，但例子跟着目标语言走：

1. *口语检验* — 最高法则。读出声来，目标语言的母语者会这样跟一个聪明的朋友说话吗？不会→改到会。只砍机械连词：
   - 中文砍「此外」「值得注意的是」
   - 英文砍 "Furthermore" "It is worth noting that"
   - 日文砍「また」「特筆すべきは」
2. *零术语* — 目标语言里聪明的 12 岁孩子能复述。先大白话落地，再提术语名。零术语不等于浅——简单的语言能解释深的机制。"旋钮"是白话，但它解释了参数的本质
3. *短词优先* —
   - 中文：能两个字说的不用四个字。「进行分析」→「看」
   - 英文：Anglo-Saxon beats Latinate. "start" not "commence". "show" not "demonstrate"
   - 日文：和語 beats 漢語。「始める」not「開始する」
4. *一句一事* — 每句只推进一步
5. *具体* — 名词看得见，动词有力气。用目标文化里的人和事：
   - 中文：「张三说项目要黄了」
   - 英文："Alice said the project's dead."
   - 日文：「太郎がプロジェクトは終わりだと言った」
6. *开头给理由* — 第一句让人想读下一句
7. *结尾留东西* — 最后一段给读者一个意外角度或带走的想法。不重复前文，不写标准总结（「有用吗？危险吗？」式的收尾是垃圾）
8. *不填充* — 删开场白、拐杖词、夸大象征
9. *信任读者* — 说一遍够了
10. *诚实* — 想不清楚就说想不清楚

## 工具箱（选用，不必全用）

- *类比* — 从目标文化的日常经验里找。好类比承重、多层、自明。检查目标语言的动宾搭配/collocation 是否自然。有多个候选类比时，留承重最大的——删掉它文章是否塌？塌→必须留
- *好问题* — 找读者的卡点，变成问题
- *裂缝* — 模型/类比哪里不够？让读者自己感到
- *画面* — 闭眼能看到的场景。场景必须是目标读者熟悉的
- *故事* — 一个具体的人遇到一个具体的问题。人和问题都要贴近目标文化
- *反问入链* — 遇到隐含前提，用问题打开
- *图* — 概念涉及空间关系、流程、层级时，用 Mermaid 图（见格式约束）。图要帮读者看到结构，不是装饰

## 格式约束

### Markdown 语法

- 加粗用 `**bold**`
- 标题层级从 `#` 开始，不跳级
- 正文无子标题——全文只有文件标题 `#`，正文用段落自然分隔

### 图表：Mermaid 优先

概念涉及结构、流程、关系时，优先用 Mermaid 图。通过 Kroki 服务渲染为 PNG 嵌入：

```
![图表描述](https://kroki.io/mermaid/png/{COMPRESSED_BASE64})
```

生成步骤：
1. 写 Mermaid 代码（flowchart / sequence / mindmap 等，选最贴合概念的类型）
2. 用 zlib 压缩后 base64url 编码：`echo -n '<mermaid_code>' | python3 -c "import sys,base64,zlib; print(base64.urlsafe_b64encode(zlib.compress(sys.stdin.buffer.read(),9)).decode())"`
3. 拼成上面的 URL，用 `![描述](url)` 嵌入

Mermaid 代码要求：
- 节点文字用目标语言
- 保持简洁——节点不超过 10 个，层级不超过 3 层
- 不画装饰性的图，只画帮助理解结构的图

不需要图的文章就不画。硬塞的图比没有更糟。

退路：如果 Mermaid 表达不了（比如纯空间布局），用 ASCII Art（纯 ASCII 字符：`+ - | / \ > < v ^ * = ~ . : # [ ] ( ) _ , ; ! ' "` 和空格，放在 code block 里）。

### 文件规范

- 时间戳：`date +%Y%m%dT%H%M%S`
- 可读时间：`date "+%Y-%m-%d %a %H:%M"`
- 文件名：`{时间戳}--plain-{简短标题}__plain.md`
- 输出目录：`~/Documents/notes/`

### YAML Front Matter

```yaml
---
title: "plain-{简短标题}"
date: "{YYYY-MM-DD Day HH:MM}"
tags: [plain, atom]
identifier: "{YYYYMMDDTHHMMSS}"
source: "{URL 或来源描述}"
---
```

文件写入后报告路径。

## 执行

### 0. 确定目标语言和文化

按「判断目标语言」的优先级确定。如果不确定，问用户。确定后锁死——全文一种语言，不夹杂。

### 1. 获取内容

URL → WebFetch | 文本 → 直接用 | 文件路径 → Read | 概念 → 直接解释 | 书名/论文名 → WebSearch

### 2. 写

形式自由。从工具箱里选最适合这个主题的方式。

所有例子、类比、场景、人名用目标文化的素材。输出是一篇从第一行流到最后一行的连贯文章。全文只有文件标题，正文无子标题。

如果概念有结构性（流程、层级、因果链），考虑是否一张 Mermaid 图比三段文字更清楚。是→画；不是→不画。

禁止：
- 结构标签（`## 类比` / `## 裂缝` 等）
- 指向写作过程的元评论（「打个比方」"Let me explain" 「説明しますと」）
- 文化混搭（英文文章里出现「微信」、中文文章里出现 Thanksgiving）

### 3. 过红线

先查骨架（结构级）：

- 查完整——读者读完能自己搭起心智模型吗？概念有"是什么"和"怎么运作"两层，不能只写第一层就收手
- 查承重——每个类比做删除测试：删掉它文章是否塌？塌→必须留，不塌→可以砍
- 查结尾——最后一段是不是全文最弱的一段？删掉它读者是否毫无损失？是→重写

再扫句子（表面级）。逐条过红线清单。额外检查：

- 破公式——否定式排比全文不超过两处，三段式改两项或四项
- 变节奏——长短句交替，段落结尾多样
- 杀金句——空洞的格言杀掉（「知识改变命运」式的）；真正压缩的洞察留着——结论自然简短不算金句
- 查跳跃——每步逻辑可追？前句说 A，后句跳到 B→补桥
- 查语感——目标语言的搭配自然吗？
  - 中文：动宾搭配天然？
  - 英文：collocation natural? No "conduct an analysis"—just "look at"
  - 日文：助詞正しい？語感自然？
- 查图——Mermaid 图节点文字是目标语言？图真的帮助理解？删掉它文章是否更难懂？

扫完列修改清单（哪句触发什么，改前→改后）。清单不写入文件。

### 4. 生成 Markdown 文件

按文件规范获取时间戳，写出 YAML front matter + 正文，存入 `~/Documents/notes/`。

## 验收

- *Grok*：读完能用自己的话复述核心
- *零术语*：目标语言里 12 岁孩子能跟上
- *记得住*：读完脑子里留下了什么——一个画面、一个问题、一个转折
- *想读完*：从头到尾没有想跳过的段落
- *无违和*：目标读者不会觉得"这是翻译过来的"——读起来像母语者写的
