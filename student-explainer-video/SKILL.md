# 学生科普动画

把知识点变成学生能跟着思考的中文动画。默认采用 Remotion；已有项目或用户指定工具时沿用它。只做用户当前请求的阶段：音色咨询不自动重做整部视频，修改旁白也不无故重写课程。

## 教学与口吻

- 从上下文确定年龄、已有知识和本片要解决的一个问题。勾股定理可以默认面向初中生，其他主题按实际受众判断。缺失信息影响难度时简短询问，同时推进不依赖答案的工作。
- 先核对数学、科学和图形关系，再设计吸引力。区分例子、直观解释与一般性证明。精确图形用可验证的坐标和矢量图，生成式图片适合装饰，不承担精确证明。
- 采用“提出可猜的问题 → 留思考时间 → 动画验证 → 解释原因 → 简短迁移题”的节奏，按内容调整，不机械套满每个环节。
- 像亲切的老师带学生发现答案。短句、有重音、有停顿；兴趣来自预测、变化和揭晓。避免持续亢奋、幼儿化称呼和与知识无关的笑点。
- 写讲稿或分镜时读 [教学编排](references/teaching.md)。

## 配音选择

- 用户指定声音时优先沿用。未指定时默认用 ListenHub 的“猴哥”（孙悟空腔，有趣、有表现力，需要 `LISTENHUB_API_KEY`）；要正经讲解可试苏哲、原野，女声可试高晴、晓曼。没有密钥时用 Edge 的云希（男）、晓伊（女）。音色标签只是筛选线索，实际中文试听决定是否适合。
- 用户在选声音时，提供同一段 15–25 秒讲稿的 2–3 种 AI 配音。用户已要求直接完成视频时，选择合理默认并继续；试听不构成必须等待确认的关卡。
- 优先使用已可用且符合用户选择的服务。默认引擎 ListenHub（`--engine listenhub`）走官方 OpenAPI，多音字和语气最稳，按字符计费；密钥只从环境变量 `LISTENHUB_API_KEY` 读取，不写进工程、命令参数或输出。没有密钥时用 `--engine edge-tts`：Edge 是非官方端点，偶发 NoAudioReceived 或连接挂起，脚本会自动重试三次；仍失败时稍后用新目录重跑，这不说明音色不可用。无网络或不想依赖任何在线服务时用 `--engine kokoro`（本地 Kokoro-82M 中文模型，100 个编号音色）；Kokoro 的多音字靠词典，生成前先 `--check`。只报告实际试听过的服务；要求更细致的情绪表演时，检查已有 MiniMax / Azure 接入。
- Edge 整个场景连续合成，保留上下文；ListenHub 和 Kokoro 按句合成后拼接，句间停顿由脚本统一控制，句子边界按样本计算。自然感按顺序来自：自然标点与停顿、可朗读的公式写法、合适的语速；做完仍机械，再换音色或引擎。
- 实际生成时读 [配音工具与选择](references/voices.md)，使用 `scripts/narrate.py` 获取音频、真实时长、句子边界和每种声音的独立时间线。

## 动画、同步和交付

- 先确定讲稿和配音，再按真实音频时长安排场景、动画和字幕。通过关键句对应视觉事件。
- 每个场景只突出一个关系。颜色、字体、片头片尾署名来自 `templates/remotion/video.config.json`，场景里不另选颜色。提问后可停 1–2 秒（输入 JSON 的 `pauseAfter`）；关键推理放慢，转场简洁。
- 换声音后重新计算时间线。双声版本通常分别渲染，分别交付字幕；只有经过句子级对齐，才让两种声音共用同一视觉时间线。
- 制作或重渲染视频时读 [Remotion 与交付](references/production.md)。本机若有 `remotion-best-practices`，可按需使用其相关规则；本 skill 不依赖其存在。
- 检查概念正确性、音频完整性、首尾及关键帧、字幕可读性、音画对应。真实试听工具可用时试听；交付说明里分开写已真实试听的内容与仅通过解码检查的内容。
- 完整视频任务交付 MP4、讲稿、SRT 和可编辑工程；按需附配音和试听。中间产物放工作目录，交付物放用户指定的输出目录。交付说明里标明 AI 配音的引擎、音色和音乐来源，这些制作信息不进画面。

## 调用示例

- “用这个 skill 做一个 90 秒的勾股定理中文动画，面向初中生，男声活泼些。”
- “保持现有画面，把配音改得更自然，给我男女声各一段试听。”
- “给小学高年级讲月相变化，先设计一个让学生猜的开头，再完成视频。”
