# Remotion 与交付

## 项目和同步

沿用现有 React / Remotion 工程及其版本。新建项目时复制本 skill 的 `templates/remotion/`，按其 README 操作：片头、片尾署名、字幕样式、配色、字体都在 `video.config.json`，每部视频只改片名、副标题，片尾致谢行只放观众需要的信息（学校、频道、参考教材），配音引擎、音色、音乐来源写进交付说明，只写 `src/scenes/` 里的场景组件并在 `src/scenes/index.tsx` 登记，SRT 用 `scripts/make-srt.mjs` 生成。背景音乐由模板按 `bgm` 配置循环并在旁白期间压低，交付说明里写明曲目来源。不要复用本机绝对浏览器路径。用 SVG 或 Canvas 绘制精确图形，动画由当前帧确定，不依赖运行时随机数、CSS 时钟或墙上时间。默认可用 1920×1080、30 fps，用户指定竖屏时改布局。

将配音文件复制到工程 `public/`，转换 manifest 相对路径后使用 `staticFile()`。对每种声音分别使用：

- `scene.startFrame` 与 `scene.durationFrames`：场景 Sequence 的位置、长度。
- `scene.audioStartFrame`：音频在整片中的起始帧；在场景内部使用时减去 `scene.startFrame`。
- `scene.boundaries[*].startSeconds`：相对于该音频开头的句子提示位置。
- `track.durationFrames`：该声音版本的旁白时间线总帧数；模板在前后加片头、片尾，帧号偏移只在模板里算一次。

## 配色

颜色只在 `video.config.json` 定义，场景文件里不出现色值。背景、文字、灰、线条、中性填充各一种，对象色最多三种。每个数学对象（边 a、边 b、斜边 c……）一种颜色，从第一次出现到片尾不变：开场的梯子就是斜边，用斜边的颜色。由对象拼成的图形沿用对象的颜色或中性填充，不引入新色。同一字母在图形、公式、字幕里同色。

场景按 manifest 默认首尾相接；叠加有时间重叠的转场时，必须同步计算重叠带来的总时长变化，不能在音频、字幕使用旧时间线时直接缩短画面。

脚本使用每种声音独立时长，禁止把甲声轨的字幕或关键帧时间无修改地套到乙声轨。要共用一条视觉轨，可在句子级建立共享时间槽，每槽长度取所有音色实际时长的最大值，语句结束后补静音；需在安静处切分，保留音频样本，重新生成字幕和动画时间线。仅在场景末尾补静音不能保证场景内部讲解同步。

## 渲染与检查

- 先查看关键静帧：标题、主要关系、变形前后、公式、结尾。核对字体、遮挡、几何、字幕安全区和颜色含义。
- 导出广泛兼容的 H.264 MP4、yuv420p、AAC，开启 faststart；按目标设备选择分辨率和编码级别。
- 检查片尾截断、音画对应、字幕跨错场景。能实际播放时检查片首、主要转折和片尾，并试听公式发音。
- 用 ffprobe 查看轨道和时长；用 `ffmpeg -v error -i output.mp4 -f null -` 检查完整解码。技术解码通过不等于完成感知质量检查。
- 多页并行渲染反复超时时可尝试 `--concurrency=1`，不将单次机器故障当成通用限制。
- Remotion 首次运行要下载 Headless Shell；网络慢到无法在任务时限内完成时，用 `--browser-executable` 指向本机已有的 Chromium（如 Playwright 的 chromium_headless_shell），只在命令行传入，不写进工程配置。
- Remotion 默认输出 full range（yuvj420p），部分播放器会偏灰；渲染时加 `--color-space=bt709`，再按下面的规则核对像素格式。
- 色彩格式不兼容时先查看实际像素格式和色彩标记再转码。确认输入是 full range 才做 full→limited，避免重复转换损伤颜色。
- 浏览器播放异常时检查文件是否可解码及服务是否支持 Range 请求。内置预览失败不代表文件损坏；如实说明尚未验证的播放环境。

## 可移交文件

完整任务包含成片、显示讲稿、字幕和可编辑工程。工程应含锁文件、必要音频/素材、启动和渲染方式，不含 node_modules、缓存、凭据或本机绝对路径。双声版标清每个视频对应的字幕；确实完成共享时间线对齐后，才提供保持进度的声音切换。

交付时说明受众、时长、AI 配音引擎和音色。优先展示成片或试听，不把中间工具脚本作为学生使用的产品界面。
